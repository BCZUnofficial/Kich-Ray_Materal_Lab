# Аудит Material Lab 0.10.0

Дата: 23 октября 2026. Основа: ранее переданные исходники 0.9.2, восстановленные поверх текущего GitHub-проекта. Проверены интерфейс, управление, материалы и кисть, DDS-экспорт, рендерер, загрузчики OGF/OMF и сборочная конфигурация.

## Что перестроено

### Интерфейс

Старая архитектура держала страницы и десятки Win32-контролов отдельными дочерними окнами. Исправления скрытия и порядка перерисовки не устранили повторяющееся смешивание страниц. Эта система удалена из рабочего приложения.

Новый интерфейс использует включённый в исходники Dear ImGui v1.91.9b. За кадр рисуется одна активная страница с собственной областью отсечения и прокруткой. DirectX рисует модель в отдельную текстуру, которую интерфейс показывает рядом с панелью. Кнопки инструментов расположены под изображением и переносятся по ширине. Диалог выбора материалов ограничен размерами окна; большой список прокручивается. Масштаб шрифта и размеры элементов обновляются при смене DPI.

`EditorUI` описывает интерфейс, `WinApp` связывает действия с файлами и управлением, `Renderer` рисует сцену, `MaterialDocument` хранит редактируемый материал. Действия интерфейса выполняются после построения кадра, чтобы загрузка модели не меняла список мешей во время его обхода.

### Нормали, кисть и история

- Выбор кисти не меняет силу нормалей, Y-ориентацию или данные материала. Настройки просмотра отделены от настроек генерации.
- Генерация выполняется явно кнопкой; перемещение ползунков не стирает мазки.
- Операции разделены на добавление/убирание рельефа, повышение/понижение высоты и блеска, усиление/смягчение деталей. Переключение направления кисти не инвертирует normal map.
- Убран предел рабочего слоя 1024 пикселя: редактируется исходное разрешение до 4096×4096. Просмотр до 768 пикселей не меняет разрешение экспорта.
- Один мазок — одно действие истории. Повторные точки одного мазка используют максимальное покрытие; следующий мазок накапливается отдельно.
- Добавлен Redo. Очистка отменяется, нулевые мазки не создают историю. Лимит истории — 64 действия / 64 МиБ, минимум последнее действие сохраняется даже при превышении бюджета.
- `.krlab` сохраняет исходную пару и редактируемые слои. У файла есть контрольная сумма; запись заменяет предыдущий файл только после успешной подготовки. Ошибка открытия сохраняет текущее состояние.

## Проверка референсов из ТЧ

Использованы предоставленные `act_bandit_bump.dds` и `act_bandit_bump#.dds`: оба 1024×1024, DXT5, 11 mip-уровней, по 1 398 256 байт. Оригиналы не изменялись и не включены в архив программы.

Сверка выполнена с исходным X-Ray:

- [sload.h — распаковка и освещение](https://github.com/OpenXRay/xray/blob/d7b23596a70374d8a7ffda0e98852f93ce985182/trunk/resources/shaders/r2/sload.h)
- [NormalMapGen.cpp — конвертер SDK](https://github.com/OpenXRay/xray/blob/d7b23596a70374d8a7ffda0e98852f93ce985182/trunk/xrDXT/NormalMapGen.cpp)

Подтверждено: `_bump.agb` хранит компоненты нормали; `_bump#.rgb` — поправку; `_bump.r` — кодированный блеск; `_bump#.a` — высоту. Движок намеренно умножает Z нормали на 0,5 после распаковки. Этот эффект сохранён ровно один раз. Удалять его как «ошибку резкости» означало бы отклониться от рендера ТЧ.

При неизменённом просмотре изменённых байтов: **0**. Изменение только блеска меняет байтов в каналах нормали: **0**. Исходная DDS-пара, загруженная в текущем запуске и оставленная без правок, экспортируется точной копией обоих файлов.

При повторном BC3-кодировании уже декодированного референса:

| Измерение | Результат |
| --- | ---: |
| Средняя угловая ошибка нормали с поправкой ТЧ | 2,291510° |
| 95-й процентиль | 5,861666° |
| Максимум | 49,093457° |
| RMSE блеска в пространстве шейдера, диапазон 0–1 | 0,006156 |
| RMSE высоты, диапазон 0–1 | 0,000583 |

Это ошибки повторного сжатия конкретного материала, а не гарантия качества любых текстур. Редкие большие угловые ошибки показывают пределы текущего BC3-кодировщика. Неправленые оригиналы поэтому сохраняются без повторного сжатия. После открытия `.krlab` доступна декодированная база, поэтому DDS экспортируется с новым сжатием.

SDK использует остаточную поправку `2/3` ошибки. На данном референсе и текущем кодировщике полная поправка дала меньшую среднюю ошибку: 2,291510° против 2,327155°. Поэтому оставлена полная поправка. Экспорт использует сохранённые упакованные каналы материала; прежняя полная перепаковка слоёв давала среднюю ошибку 3,334233°. Формат совместим с декодированием ТЧ, но результат генерации не заявляется побайтной копией SDK. Mip-уровни нормалей фильтруются как векторы с нормализацией; блеск фильтруется в декодированном пространстве.

Числа, SHA-256 исходных файлов и исходников проверки находятся в `tests/reference_audit_act_bandit.json`. Повторение: собрать цель `reference-audit` через CMake и передать два пути к DDS. Для отчёта с хешами предусмотрен Python-скрипт в `tools`.

## Другие исправления

| Область | Обнаруженная ошибка и исправление |
| --- | --- |
| DDS-запись | В заголовке указывался размер одной строки блоков вместо полного верхнего уровня; исправлен linear size и проверка mip chain. |
| DDS-чтение | Учтён padding строк несжатого изображения; устранены опасные сдвиги/маски; отклоняются неподдерживаемые DX10 arrays/cubes и повреждённые уровни. Корректные 4096² разрешены. |
| OGF | Проверяются границы chunks, индексы, иерархия костей и циклы. Отсутствующие IK-данные больше не оставляют нулевые inverse-bind матрицы. Ошибки встроенных движений не скрываются. |
| OMF | Проверяется соответствие костей, ограничена память декодированных ключей, chunks индексируются один раз. Неудачная загрузка сохраняет прежние анимации. |
| GPU-материалы | Текстуры пары и геометрия готовятся до замены рабочего состояния; ошибка создания ресурсов не смешивает старые и новые компоненты. |
| Выделение | Проверяются локальные границы окна вывода; bind pose восстанавливает bounds, используемые для picking и сортировки прозрачности. |
| Шейдер | Добавлена защита от вырожденного tangent basis. Сохранена прозрачность diffuse, включая alpha-aware picking и контур. |
| Экспорт пары | Оба файла сначала готовятся отдельно. При обычной ошибке замены выполняется откат, чтобы не оставить половину новой пары. |

## Проверки и границы аудита

В проекте есть отдельные проверки камеры и UV-мазков, математических операций кисти, документа/истории/сохранения, загрузчиков и настоящего `DrawEditorUI`.

Тест интерфейса строит **576 кадров**: 6 вкладок, 4 размера окна, масштаб 100/125/150/200%, повторные переключения. Проверяются одна активная панель, отсутствие пересечения панели/вьюпорта/кнопок и корректные scissor-границы. Дополнительно подаются события мыши: кнопка BR, недоступная кнопка, прокрутка и сохранение отдельных scroll-позиций. Программно отрисованные кадры интерфейса просмотрены визуально. Эти проверки не заменяют запуск DirectX-окна на Windows.

Загрузчики проверены валидными синтетическими файлами, повреждёнными заголовками и иерархиями, 600 детерминированными мутациями и обоими предоставленными DDS. Проверки документа включают размер более 2048 пикселей, NPOT/периодические края, отмену/повтор, неудачную запись и повреждённые `.krlab`. Все семь тестов прошли в Release и с AddressSanitizer/UndefinedBehaviorSanitizer. Проверка утечек на данном хосте отключена. Полная Windows x64 кросс-сборка также прошла; MSVC и WARP здесь не запускались.

При потере графического устройства программа пытается сохранить изменённые материалы в `%TEMP%/MaterialLab-recovery` и показывает путь. Если сохранение не удалось и пользователь отменил ручное сохранение, документы остаются в памяти до повторной попытки закрытия. Этот путь включён в исходники и проверен разбором кода; реальная потеря GPU-устройства на Windows здесь не моделировалась.

### Что ещё требует проверки на рабочем компьютере

- Нативный запуск Visual Studio / D3D11 на Windows, драйвер видеокарты, перенос окна между мониторами и реальные OGF/OMF пользователя. Здесь доступны переносимые тесты и Windows-кросс-компиляция; успешный запуск нативного Windows smoke test в этой среде не заявляется.
- Пересекающиеся полупрозрачные поверхности могут давать артефакты обычной сортированной прозрачности.
- Пара DDS — два файла: откат обрабатывает обычную ошибку файловой операции, но не является общей crash-atomic транзакцией при отключении питания.
- Сеанс хранит материал, а не весь проект: модель/diffuse/анимации и история Undo в него не входят.
- Не реализованы полноценные игровые IK, смешивание анимаций и внешние OGF_CHILDREN_L. Все произвольные игровые модели этим аудитом не охвачены.

Полный аудит здесь означает проверку всех основных подсистем и исправление найденных воспроизводимых ошибок; он не означает доказанное отсутствие любых ошибок.
