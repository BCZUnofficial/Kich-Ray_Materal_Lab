## Что означает соответствие движку

Нормаль восстанавливается как `bump.abg + bumpX.rgb - 1`. Затем `z *= 0.5` применяется **один раз**, после чего направление переводится через базис поверхности. Gloss — `bump.r²`. Это преднамеренное усиление наклона в SoC, а не ошибка, которую следует убрать только из редактора.

Для прямого света используется таблица 128×256×4, включая квантование `floor(value * 255.5)` и принудительный последний texel. Проведено сравнение всей таблицы с функцией из указанного коммита KichRay: **0 различающихся texel из 131 072**. Дробный класс THM интерполирует соседние slices с переходом 3 → 0, как R2 `tex3D` с W wrap. Цвет света умножается на интенсивность; для блика средняя энергия ниже 1 возводится в степень 2/3, как `u_diffuse2s`. Используется `r2_gloss_factor = 1`.

`models\selflight` и `models\selflightl` определяются по shader-ссылке OGF: их normal-проход плоский, накопление эмиссии соответствует исходным шейдерам (8 и 0.5). Простое повышение Gloss не создаёт свечение. Имя `selflight` без `models` не приравнивается к ним: его shader-проход в исходниках другой.

Это просмотр материала под управляемым прямым светом. Он не загружает окружение игрового уровня, погоду, тени, cubemap, detail mapping, parallax, lightmap, экспозицию, bloom и произвольные модификации shader-кода. Не учитываются переопределения `textures.ltx` и runtime-настройки материала. Без проверки конкретной сцены нельзя обещать покадровое совпадение с игрой. Для статического R1 этот R2-профиль не является эталоном.

Если THM содержит выключенный bump, интерфейс сообщает об этом: сама запись DDS-пары не подключает bump к игровому материалу. При custom bump-ссылке в THM имя экспортируемой пары необходимо согласовать с этой ссылкой. Пресеты стекла и металла меняют микрорельеф, не прозрачность или шейдер.

## Формулы пресетов

Используется стандартная связь нормали с градиентом высоты: `n = normalize(-dh/du / 16, -dh/dv / 16, 1)`. Производные вычисляются центральными разностями. `N_k` — периодический value noise на сетке k×k с фиксированным seed и интерполяцией `t²(3−2t)`, `τ = 2π`.

| Пресет | Поле высоты h(u,v) |
| --- | --- |
| Стекло | `0.08 N_3` |
| Ткань | `0.055 (cos(16τu)+cos(16τv)) + 0.025 cos(16τu)cos(16τv)` |
| Металл | `0.015 sin(32τv) + 0.008 N_47` |
| Бетон | `0.09 N_8 + 0.045 N_23 + 0.025 N_47` |
| Кожа | `0.04 N_8 − 0.065 max(0, 2N_23−1)^4 + 0.006 N_47` |

Коэффициенты — авторские художественные настройки, не измеренные свойства материалов. Подход с производными высоты основан на [PBRT — Bump Mapping](https://www.pbr-book.org/3ed-2018/Materials/Bump_Mapping) и [NVIDIA — Bump Map Filtering](https://developer.download.nvidia.com/assets/gamedev/docs/bumpmap.pdf). Все пять карт проверяются на воспроизводимость, различимость, конечные нормализованные направления и наличие рельефа. Дополнительно каждый пресет наносится при стандартной силе кисти 35%: проверяется изменение рабочей нормали и сохранение результата после BC3-кодирования. Амплитуда стекла подобрана так, чтобы правка не исчезала при 8-битном округлении.

## Проверки

- Полные приложения x64 и Win32 собраны MinGW-w64/GCC 13.2 с DirectXMath. MSVC и Windows CI здесь не запускались из-за отсутствия доступа на запись в GitHub. Собранные EXE включены как сборки для проверки на Windows.
- CMake/GCC: 6 наборов регрессионных тестов, все прошли.
- ASan + UBSan: те же 6 наборов прошли с `detect_leaks=0`; LeakSanitizer в этой среде не получает доступ к `/proc/.../task`. Проверка утечек здесь не подтверждена.
- ImGui: 576 кадров на четырёх размерах и четырёх DPI, изоляция панелей; реальные события мыши для ползунков, запрет клавиатурной регулировки, Apply, отключённые поля и прокрутка popup к последней анимации. Проверены изображения действующего интерфейса.
- Проверены полная DDS mip-цепочка, отказ при повреждённом нижнем mip, идентичность preview-cache и записанных DDS, нулевой Gloss на всех mip, восстановление Gloss без потерь рабочих данных.
- В Windows smoke-test добавлены реальные ответы Yes/No/Cancel на окно подтверждения, изменение кадров от ползунков/интенсивности/фона, DDS upload и виды по осям. Windows smoke-test в этой среде не выполнен: Wine не может создать служебный socket (`Operation not permitted`). Запуск EXE, runtime-компиляция HLSL и сравнение с кадром игры остаются непроверенными.

GitHub отклонил создание ветки с `403 Resource not accessible by integration`; доступные учётные данные для `git push` отсутствуют. Поэтому изменения передаются полным исходным проектом и патчем к указанному базовому коммиту. Основная ветка репозитория не изменена.

## Исправление сборки MSVC от 26.10.2026

По логу пользователя установлен конфликт имени локальной переменной `small`
с макросом Windows SDK `#define small char`. Переменная в `WinApp.cpp`
переименована в `resizedFrame` во всех трёх местах. Локальная строка `value`
в обработчике цвета фона переименована в `backgroundValue`, что устраняет C4457.

Исходная ошибка воспроизведена принудительным включением того же макроса
после заголовков: старый файл не компилируется, исправленный проходит для
x64 и Win32. Полные сборки обоих приложений MinGW-w64 повторно прошли.
Это проверка совместимости с конкретным макросом; запуск MSVC в этой среде
по-прежнему не выполнялся. Логика редактора и форматы файлов не менялись.
